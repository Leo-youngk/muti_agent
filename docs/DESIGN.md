# 设计方案：纸上顾问团（Warm Paper / Private Advisory）

> 面向「顾问团」核心功能的 UI 设计规格。配套可视化预览：`design/preview.html`（浏览器直接打开）。
> 设计方法基于 impeccable 技能；本文件同时充当 `.impeccable.md` 的设计上下文记录。

## 1. 设计上下文

- **目标用户**：偏好本地私有部署、希望用多个差异化思维视角审视同一个问题的个人决策场景使用者。
- **核心任务**：输入问题 → 实时观看四位顾问各自流式给出结构化判断 → 快速比较立场分歧 → 追问单个顾问或发起全员辩论 → 管理多个对话线程。
- **品牌气质**：温润、人文、可信赖的「私人顾问团」。像收到几封措辞认真、立场鲜明的亲笔意见书，而不是面对一个冰冷的聊天机器人。
- **平台**：移动优先 PWA（iOS 可安装、刘海屏 safe-area），桌面端为增强体验。
- **技术约束**：Next.js 16 + React 18 + Tailwind；token 级流式渲染；每顾问独立状态机（thinking / done / error）。

## 2. 设计方向

**概念：纸上顾问团。** 延续现有暖米色系并升级为「精制纸面」质感：纸色底、墨色文字、发丝线分隔、衬线标题，每位顾问有一张收敛而耐看的身份色。界面像一封封排印精良的意见书，克制、安静、有分量。

**记忆点（Differentiation）：「立场一览」StanceStrip。** 每轮顾问回答的最上方有一条极薄的立场汇总条：四个彩色小点 + 「2 支持 · 1 反对 · 1 待定」。用户在滚动阅读任何一条长篇判断之前，先一眼看清顾问团的分裂格局——这正是多 Agent 产品区别于单聊机器人的核心价值，当前 UI 里完全缺失。

**辅助记忆点：意见书式顾问卡。** 顾问名与「核心判断」使用衬线体，卡片以顾问色发丝左边线收束「核心批评」区块，整体读感像一份署名备忘录。

## 3. 信息架构

四个界面状态，均在单栏对话流内完成，无页面跳转：

1. **空状态（顾问名册）**：产品名 + 衬线大标题 + 四顾问名册卡（头像 / 名字 / 座右铭）+ 示例问题列表。教育用户「这里有一群顾问，各有立场」。
2. **对话主屏**：顶栏（菜单 + 线程标题 + 更多）→ 消息流（用户气泡 / 顾问面板：StanceStrip + 若干 AdvisorCard + 面板操作行）→ 底部输入条（模型 chip + 发送）。
3. **追问 / 辩论模式**：面板上方细分隔线标签（「追问模式」/「辩论轮」）+ 输入条上的追问 chip，可取消。
4. **侧栏抽屉**：新的顾问团按钮 + 线程列表（当前线程高亮）+ 底部设置入口。移动端为左滑抽屉 + 遮罩。

## 4. 视觉系统

### 4.1 色彩（oklch 定义，禁止纯黑纯白）

| Token | oklch | 近似 hex | 用途 |
|---|---|---|---|
| `--paper` | 97.2% 0.008 85 | `#F7F4EE` | 页面底色 |
| `--paper-raised` | 98.6% 0.006 85 | `#FBF9F5` | 输入条、名册卡等浮起面 |
| `--ink` | 28% 0.015 70 | `#33302A` | 主文字 |
| `--ink-2` | 40% 0.015 70 | `#4A463F` | 正文（推理段落） |
| `--muted` | 55% 0.012 70 | `#6E6759` | 辅助文字（须过 AA 4.5:1） |
| `--faint` | 65% 0.010 75 | `#8E867A` | 占位符、时间戳等弱信息 |
| `--hairline` | 88% 0.008 80 | `#E4DFD6` | 发丝分隔线、卡片描边 |
| `--accent` | 50% 0.15 30 | `#B23E26` | 朱砂：发送键、深入辩论、当前线程等关键动作，使用面积 ≤10% |
| `--accent-soft` | 94% 0.03 35 | `#F3E3DC` | accent 的浅底（hover/选中底） |

所有中性色带微量暖色（chroma 0.006–0.015），与纸面气质统一。

**顾问身份色**（保留红/蓝/金/紫识别度，收敛饱和度以融入纸面）：

| 顾问 | oklch | 近似 hex |
|---|---|---|
| 乔布斯 | 52% 0.14 28 | `#B23A2C`（氧化红） |
| 马斯克 | 50% 0.09 235 | `#3E6E8E`（钢青） |
| 巴菲特 | 55% 0.10 80 | `#9C7A28`（赭金） |
| 芒格 | 50% 0.09 305 | `#7A5C9E`（灰紫） |

**立场语义色**：支持 `#3F7A4E`（松绿）、反对 `#B5433A`（砖红）、有条件支持 `#A8742A`（赭）、待定 `#857D71`（暖灰）。立场一律「彩色点 + 文字」双编码，不单独依赖颜色。

### 4.2 字体排印

- **衬线（意见书标题感）**：`"Noto Serif SC", "Songti SC", "STSong", "SimSun", serif`。用于：产品名、空状态大标题、顾问中文名、核心判断。
- **无衬线（正文）**：`-apple-system, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。用于：推理正文、UI 控件、英文。
- **五级字号**（固定 rem 标尺，App UI 不用流体字）：12（标签/元信息）/ 13（辅助）/ 15（正文，行高 1.75）/ 17（核心判断，衬线 600）/ 22（空状态大标题，衬线 600）。移动端正文不得低于 16px 等效可读性，正文采用 15px + 1.75 行高保证中文长文阅读。
- 数字进度用 `font-variant-numeric: tabular-nums`。

### 4.3 空间与形状

- 4pt 间距标尺：4 / 8 / 12 / 16 / 24 / 32 / 48。消息流卡片间距 24，卡片内部段落间距 16，标签与内容间距 8。
- 圆角：顾问卡 14、用户气泡 18（收信角 4）、callout 10、按钮/徽标全圆角。
- 深度：不用投影堆叠；以 1px hairline + 底色差分层。仅输入条与抽屉允许极浅阴影（ink 6% 透明度）。
- 阅读列宽：对话内容 max-width 672px 居中；移动端左右留白 16。

### 4.4 动效

- 时长令牌：`--dur-1: 120ms`（按压反馈）/ `--dur-2: 240ms`（hover、chip 出现）/ `--dur-3: 400ms`（卡片入场、抽屉）。
- 缓动：`cubic-bezier(0.25, 1, 0.5, 1)`（ease-out-quart）。只动画 transform 与 opacity。
- 顾问卡入场：fade + translateY(8px)，400ms，按顾问依次 stagger 80ms（与后端 800ms 错开调度节奏呼应）。
- 思考中：三圆点 1.2s 脉冲（顾问色）；流式中：顾问色呼吸小点。
- `prefers-reduced-motion: reduce` 时：取消位移动画与 stagger，仅保留 200ms 淡入；进度条与加载指示保留功能。

## 5. 组件规格与状态

### 5.1 StanceStrip（新组件，记忆点）

位置：每个顾问面板（panel）顶部，随消息流滚动，不 sticky（避免与输入条抢注意力）。内容：四个 8px 立场色点 + 汇总文案「2 支持 · 1 反对 · 1 待定」。流式进行中显示「立场形成中…」（faint 色），每有一位顾问完成即更新。面板仅一名顾问（追问）时不显示。

### 5.2 AdvisorCard（核心组件）

结构：左侧 36px 圆形头像（顾问色底 + 白色字符）→ 名字行（衬线中文名 15 600 + 英文小字 + 立场 pill + 流式呼吸点）→ 内容区。

| 状态 | 表现 |
|---|---|
| thinking（无内容） | 三圆点脉冲 + 两条纸色骨架行（shimmer），骨架宽度 80% / 60% |
| thinking（流式中） | 已提取字段逐段出现（核心判断 → 推理 → 批评），末尾「正在生成…」呼吸点 |
| done | 立场 pill（色点 + 文字 + 浅底）；核心判断衬线 17/600；推理 15/1.75；核心批评 callout（顾问色 2px 左边线 + 顾问色 5% 浅底，标签「核心批评」小字加粗）；「展开完整判断 ▾」渐进披露（关注焦点 / 要求改变 / 如何切入 / 他的盲点，盲点用斜体弱色）；追问按钮（顾问色 ghost pill） |
| error（无判断） | 砖红浅底提示条（⚠ + 失败原因）+「重试」描边按钮；不影响其他顾问 |
| 被追问目标 | 头像外 3px 顾问色 30% 光晕，提示「正在追问此人」 |

复制按钮仅桌面 hover / 移动端长按浮现，避免常显噪音。

### 5.3 用户气泡

右对齐，暖灰底（`#E9E3DA`），圆角 18 收角 4，最大宽 80%，正文 15。不使用 accent 色——accent 只留给系统关键动作。

### 5.4 面板操作行

整轮完成后居中显示：「重新生成」（faint ghost）+「深入辩论」（accent 描边 pill，辩论是产品高光动作，用唯一 accent 强化）。追问轮 / 辩论轮不重复显示「深入辩论」。

### 5.5 输入条

纸面浮起卡（raised 底 + hairline + 6% 浅影），圆角 18。内部：多行输入（占位符「向顾问团提问…」，faint 色且过 AA）+ 发送键（accent 实心圆 32px，纸色纸飞机图标；流式中变为停止方块）。底部工具行：模型选择 pill + 设置齿轮。追问模式：输入条上方出现顾问色 chip「追问 乔布斯 ✕」，输入条描边变顾问色 30%。safe-area 底边距 `max(8px, env(safe-area-inset-bottom))`。

### 5.6 空状态（顾问名册）

居中窄栏（max 360px）：衬线 22px 大标题「把一个问题，交给四位顾问」→ 一句 faint 副标题 → 名册卡（raised 纸卡 + hairline，四行：头像 / 衬线名 + 英文名 / 座右铭，行间发丝线）→ 三个示例问题（描边列表项，左侧 16px 顾问色短竖线装饰，hover 浅底，active scale 0.98）。示例问题文案即教育：展示「什么问题适合问顾问团」。

### 5.7 侧栏抽屉

移动端：左侧滑入 280px 抽屉 + ink 30% 遮罩（400ms ease-out-quart）。内容：顶部「＋ 新的顾问团」accent 描边主按钮 → 线程列表（当前项 accent-soft 底 + 左侧 3px accent 竖线，其余项 hover 浅底；每项两行：标题 + faint 时间）→ 底部发丝线 + 设置入口。桌面端（≥1024px）：抽屉常显为固定侧栏，无遮罩。

## 6. 交互规范

- **主流程**：输入问题 → 发送键转停止 → 用户气泡 + 面板依次入场 → StanceStrip 实时汇总 → 全部完成后出现操作行。任何时刻可停止（停止后面板保留已生成内容并可重试未完成顾问）。
- **渐进式披露**：默认只看立场 + 核心判断 + 推理 + 批评；focus/demand/approach/blind_spot 收入「展开完整判断」。
- **空/错/载全覆盖**：空状态有教育性名册；单顾问失败不阻塞他人、可单独重试；全局错误（缺 Key、限速）以顶部 toast 呈现（砖红浅底，4s 自动消失，可手动关闭）。
- **滚动**：新消息且用户贴近底部时平滑跟随；用户上翻时显示「回到底部」浮钮（raised 圆形，右下，距输入条 12px）。
- **触控**：所有可点目标 ≥44×44px（图标按钮用伪元素扩热区）；按钮 active 一律 scale 0.97 + 120ms。
- **文案**：不重复用户已可见信息；按钮一律动词开头（重新生成 / 深入辩论 / 展开完整判断）；错误文案给原因与下一步（如「未配置 API Key，请在设置中填写」）。

## 7. 响应式规则

- 移动优先单栏；≥768px 对话列保持 672 居中，两侧留白；≥1024px 侧栏常显（grid: 280px + 1fr）。
- 顾问卡用容器查询：容器 ≥520px 时头像增大至 40px、名字行不换行。
- 抽屉、输入条、toast 均适配 safe-area。移动端不隐藏任何关键功能。

## 8. 可访问性

- 正文/辅助文字对比度 ≥ 4.5:1（muted 及以上）；立场 pill 文字 ≥ 4.5:1 且有色点双编码。
- 焦点环：2px accent 40% 外描边，键盘可达全部操作（含追问、展开、重试）。
- `prefers-reduced-motion` 全量支持；流式区域用 `aria-live="polite"` 按顾问完成时播报「乔布斯已完成」。
- 不禁用缩放；字号用 rem。

## 9. 验收标准

1. `design/preview.html` 在浏览器打开后，移动视口（375px）下无横向滚动、无文字重叠，三个界面状态与令牌面板完整呈现。
2. 设计令牌（色彩 / 字号 / 间距 / 动效）在本文件第 4 节完整定义，可直接映射为 Tailwind 配置。
3. 核心组件状态机（thinking / streaming / done / error / 被追问）在预览中均有可视实例。
4. 新增 StanceStrip 组件有明确位置、内容规则与降级规则（单顾问不显示）。
5. 所有文字色对纸底对比度 ≥ 4.5:1；立场双编码；动效含 reduced-motion 降级。
6. 与现有代码的组件边界一一对应（ChatView / AdvisorCard / InputBar / Sidebar / 空状态），可逐组件落地，不引入新依赖。

## 10. 假设

- 沿用四位内置顾问（红/蓝/金/紫身份色仅做饱和度收敛，不改色相），自定义顾问沿用用户自选色、自动套用同一套状态样式。
- 主持人结论（ConclusionSection）未来接线时复用顾问卡样式，身份色用 accent 朱砂。
- 深色模式本期不做；如需做，按 oklch 语义层重定义纸面为 18% 明度暖灰，而非反色。
