# 回答质量与连续对话优化（2026-10-26）

## 已确认目标

保留人物顾问的思维方式和单列文字阅读体验，让回答更贴题、有依据、可追问，并让失败、中断和模型选择准确可见。沿用 Next.js、OpenAI 兼容 SDK、独立 SSE 与浏览器持久化。

## 实施与验收

1. 提示词 V2：依据用户条件给出判断，按复杂度决定篇幅；允许信息不足和条件性结论，禁止编造经历、数字、引语和来源。仅生成当前可见的立场、核心判断与推理，旧历史字段继续兼容。
2. 有界多轮上下文：保留最近多轮的用户原文与本人回答，附较早用户背景原文；较新修正优先。其他顾问意见只在定向追问时按本次讨论取用，标明对应问题。重试不得把当前失败轮当作历史。
3. 结果完整性：最终值通过运行时字段校验才能完成；截断、超时与抢救内容标记为部分回答。停止、重试和切后台保留已显示内容；重试失败不能抹去旧内容。
4. 模型身份：服务商 ID 与模型名共同确定调用；迁移旧选择，不再补入未确认可用的预设模型。同名模型可分别选择，失效选择回到有效项或明确提示。
5. 历史快照：每轮保存参与者及模型信息，不保存密钥；关闭/删除顾问不隐藏历史。历史旧格式仍可显示、导出、追问或给出可解释的重试错误。
6. 输入与恢复：流式时可写草稿，中文输入法确认字符不发送；状态区分排队、生成、部分、停止、失败。持久化采用定期检查点和后台快照，避免持续输出让防抖一直不落盘。
7. 内容评测：纳入不少于 24 个固定真实场景（含缺信息、多轮、纠错、事实与角色差异），保存旧提示词基线，提供实际模型 A/B 运行器与人工评分表；未调用模型的检查不宣称证明内容质量。
8. 按需联网：复用已配置的检索服务，单次查证结果供全员共享；明确区分网页摘录与搜索摘要，失败可见，未配置时不编造资料。生产端维持 BYOK，避免公开接口消耗集中托管的检索密钥。

## 边界

- 不增加 LangGraph/AutoGen、数据库、账号体系或整套新 AI 框架。
- 不恢复已移除的轮次辩论、重生成与继续讨论按钮。
- 保留为修复 Worker CPU 超时引入的默认关闭 thinking 和 SSE 批量发送；深度推理模式需另做容量与质量对照后上线。
- 不覆盖现有浏览器历史、不迁移或公开凭据，不以格式解析成功代替回答完整。
- 用户最新交付边界：提交并推送 GitHub，不部署。
