# 紧凑阅读密度设计

## 问题

iOS PWA 的主阅读流已经以文字为中心，但当前 Agent 章节、字段组和段落之间的纵向距离偏大。长回答中会形成大量视觉空洞，单位屏幕可读信息过少。

## 已批准方案

采用“适度紧凑”，不做激进压缩：明显减少空白，同时保留 Agent 章节边界、结构化小标题和中文长文的呼吸感。

## 调整范围

只调整 `AgentResponseSection` 与 `ChatView` 的纵向节奏：

- Agent 章节纵向内边距由 40px 收紧到约 28px。
- Agent 标题区底部间距由 32px 收紧到约 20px。
- 立场与标题间距由 8px 收紧到约 4px。
- 结构字段之间由 28px 收紧到约 18–20px。
- 小标题与正文之间由 8px 收紧到约 4px。
- Markdown 段落与列表底部间距由 12px 收紧到约 8px。
- 普通正文行高由 28px 收紧到约 26px；核心判断维持较宽松行高以保持强调层级。
- 用户问题、讨论轮与底部操作区的外部留白同步减少约 20–30%。

不改变字体大小、内容结构、Agent 顺序、自然滚动、流式状态或最小 44px 触控区域。

## 验收标准

- 相同回答在 390×844 视口中显示更多连续正文，且不会显得拥挤。
- 章节边界仍可通过细分隔线、编号和 Agent 名称识别。
- 小标题不会与上一段正文粘连，正文没有重叠或截断。
- 320、375、390、430px 宽度无横向溢出。
- 自动测试、ESLint 与生产构建继续通过。

## 风险与约束

- 过度压缩会降低长文扫读能力，因此不把字段间距降到 12px 以下。
- 操作按钮仍保留 44px 最小点击高度，不用缩小触控区域换取密度。
- 本次不调整设置弹窗、线程抽屉或输入器布局。

## 假设

- 用户所说的“上下文行距”同时指正文行高和相邻信息块的纵向间距；视觉空白主要来自后者。

## 开放问题

- 无。若后续仍觉得松散，再基于实机截图单独调整普通正文行高，不与本次字段间距调整混在一起。
