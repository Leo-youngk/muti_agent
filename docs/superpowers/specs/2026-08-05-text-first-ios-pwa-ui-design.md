# 多 Agent 讨论室：文字优先的 iOS PWA UI 重构设计

日期：2026-08-05  
状态：设计方向已确认  
视觉参考：[text-first-ios-pwa-preview.png](./assets/text-first-ios-pwa-preview.png)

## 1. 问题

当前界面把多 Agent 讨论表现为一组卡片、头像、身份色和状态组件。它能展示“有多个 Agent”，但视觉组件挤占了正文空间，也让产品更像 Agent 控制台或品牌化顾问产品。

用户真正需要的是阅读信息：在手机上连续、完整地阅读多个 Agent 的长文本回答，并在需要时追问某一个 Agent 或继续下一轮讨论。

因此，本次重构的目标不是换一套装饰，而是把界面从“Agent 卡片流”改为“多作者长文阅读流”。

## 2. 用户与使用场景

- 主要平台是 iOS 上可安装的 PWA。
- 用户会在手机上阅读较长的中文回答，可能连续使用较长时间。
- Agent 数量是动态的，不固定为四个；同一讨论可能有 1 个、4 个或更多 Agent。
- 用户先阅读完整信息，再决定追问某个 Agent 或开启下一轮。
- 讨论需要保留 token 级流式输出、错误重试、多线程切换和模型配置能力。

## 3. 已确认的设计原则

1. **文字是产品主体。** 屏幕绝大部分面积用于问题与回答正文。
2. **单栏顺序阅读。** Agent 按配置顺序纵向排列，使用系统自然滚动。
3. **完整内容默认展开。** 不用“展开全文”隐藏正文。
4. **结构化小标题保留。** 核心判断、推理、批评、盲点等字段以文字标题组织。
5. **顺序固定。** Agent 返回速度不改变页面顺序；每个 Agent 在预定位置原位流式输出。
6. **Agent 数量动态。** 布局、文案、进度和交互不得写死为四个 Agent。
7. **阅读时不常驻输入框。** 追问或继续讨论时再唤起编辑器与键盘。
8. **不设置目录或悬浮导航。** 用户通过自然滚动阅读整轮内容。

## 4. 明确不采用的方向

- 不做卡片墙、2×2 矩阵、横向卡片轮播或仪表盘。
- 不用头像、名人肖像、彩色身份图标或大面积 Agent 身份色。
- 不用进度环、状态胶囊、统计条或装饰性动画表达“多 Agent”。
- 不使用纸张、意见书、私人顾问团等品牌或叙事隐喻。
- 不把聊天气泡作为主要内容容器。
- 不用渐变、玻璃拟态、明显阴影和大面积圆角容器。

## 5. 页面结构

### 5.1 顶栏

顶栏只包含：

- 左侧线程/菜单入口；
- 中间当前讨论标题；
- 右侧低频操作入口，例如导出和更多操作。

顶栏适配 `env(safe-area-inset-top)`。它不展示 Agent 数量、运行仪表或品牌标识。

### 5.2 用户问题

用户问题作为正文的开篇，左对齐显示，不使用聊天气泡。问题与第一位 Agent 之间使用较大的段后留白和一条 1px 分隔线。

### 5.3 Agent 回答章节

每个 Agent 是文档中的一个章节，而不是一张卡片。章节结构如下：

```text
01  Agent 名称
立场（次级文字）

核心判断
完整判断内容……

推理
完整推理内容……

核心批评
完整批评内容……

盲点
完整盲点内容……

追问此 Agent
```

章节编号根据当前 Agent 数量动态生成。所有结构化字段默认显示；没有内容的字段不渲染标题。

章节之间仅使用留白和细分隔线。Agent 名称是署名，不承担品牌或人格化装饰作用。

### 5.4 轮次结束

所有 Agent 完成后，在最后一个章节之后显示文本级操作：

- `继续讨论`
- `重新生成本轮`

只有当存在至少两个已完成回答时，才显示 `发起下一轮讨论`。具体数量由实际 Agent 集合计算，不写死。

### 5.5 输入编辑器

阅读状态下不常驻输入框。以下操作会唤起底部编辑器：

- 点击某章节末尾的 `追问此 Agent`；
- 点击轮次末尾的 `继续讨论`；
- 新线程的空状态直接进入输入状态。

编辑器作为临时底部层出现，适配键盘和 `env(safe-area-inset-bottom)`。追问时用一行纯文字说明目标 Agent，并提供取消入口。

## 6. 流式与状态行为

### 6.1 固定顺序

提交问题后，立即按配置顺序创建所有 Agent 章节。章节位置在整轮生成期间保持不变。

### 6.2 状态表达

状态只使用简短文字，不使用徽标或状态组件：

- 未开始：`等待中`
- 请求已发出：`正在思考…`
- 流式输出：逐字段原位写入；没有额外进度控件
- 完成：移除临时状态文字
- 失败：在该章节原位显示错误原因和文本按钮 `重试`

单个 Agent 失败不阻塞其他 Agent。重试仍在原章节位置输出。

### 6.3 滚动

- 用户接近底部时，流式内容可以平滑跟随。
- 用户主动向上阅读后，停止自动滚动。
- 不显示常驻“回到底部”按钮；仅在离底部较远且仍有新内容时，显示低干扰的文字入口 `查看新内容`。

## 7. 排版与视觉令牌

### 7.1 色彩

| 令牌 | 值 | 用途 |
|---|---:|---|
| 页面背景 | `#FAFAF8` | 全屏背景 |
| 主文字 | `#191B1A` | 问题、核心判断、正文 |
| 次级文字 | `#6E7471` | 立场、状态、辅助说明 |
| 弱文字 | `#909693` | 时间、章节编号等 |
| 分隔线 | `#E5E7E5` | 章节边界 |
| 交互文字 | `#0F5A54` | 追问、重试、继续讨论 |
| 错误文字 | `#A63E35` | 错误原因 |

不用每个 Agent 的身份色。颜色只表达全局语义和可交互性。

### 7.2 中文排版

- 字体：优先系统中文字体栈，避免额外网络字体影响 PWA 启动和离线阅读。
- 正文：16px，行高 1.75，字重 400。
- 核心判断：20px，行高 1.55，字重 600。
- 用户问题：19px，行高 1.65，字重 450–500。
- Agent 名称：17px，字重 600。
- 结构化小标题：12px，字重 600，使用次级文字色。
- 状态与元信息：13px，行高 1.5。
- 禁止正文小于 16px。

### 7.3 空间

- iPhone 左右安全留白：20px；小于 360px 宽时降为 16px。
- 章节内部小标题与内容间距：8px。
- 结构化字段之间：24px。
- Agent 章节之间：40px 加 1px 分隔线。
- 正文段落间距：12–16px。
- 不使用卡片内边距，因为内容不在卡片中。

## 8. 空、载、错状态

### 空状态

只显示一个简短标题、一句用途说明和输入编辑器。示例问题以普通文本链接呈现，不使用大卡片。

### 加载状态

已创建的 Agent 章节显示名称和 `正在思考…`。不使用骨架屏、跳动圆点和进度动画。

### 错误状态

错误在对应 Agent 章节中以内联文字显示，包含原因和下一步，例如：

```text
请求失败：模型服务暂时不可用。重试
```

缺少 API Key 等全局错误可以使用顶部内联提示，但不得覆盖正文。

## 9. 动态 Agent 约束

- 所有列表由实际 Agent 配置生成。
- UI 文案使用 `N 个 Agent` 或不显示数量，禁止出现固定“四位顾问”。
- 章节编号至少支持两位数；超过 99 个时继续自然增长。
- 1 个 Agent 时不显示对比或下一轮讨论入口，但追问正常工作。
- 大量 Agent 时不得一次生成昂贵的视觉组件；章节使用普通文档流并按需渲染。

## 10. 组件边界

建议将现有 UI 重构为以下职责：

- `ChatApp`：线程、设置、编辑器开关与全局错误；不承载正文样式。
- `ChatView`：问题与轮次的文档流、滚动跟随策略。
- `AgentResponseSection`：单个 Agent 的固定位置、流式字段、错误与追问入口。
- `InputBar`：改为按需出现的 `Composer`，处理普通提问与定向追问。
- `Sidebar`：保留为 iOS 抽屉，只处理线程管理，不在正文中常显。
- `SettingsModal`：继续独立，视觉上同步新的文字优先令牌，但不参与首轮重构的结构改造。

现有 `AdvisorCard` 可以原位重构后再重命名，避免一次性改变过多调用关系。

## 11. 响应式与 PWA

- 主要验收视口：320×568、375×812、390×844、430×932。
- 顶部与底部均适配 iOS safe-area。
- 键盘打开时编辑器保持可见，正文区域可滚动，不发生整页跳动。
- 不禁用系统文字选择；用户应能复制回答内容。
- 横屏与桌面只将阅读列限制在最大 680px，不引入桌面侧栏型正文布局。

## 12. 可访问性

- 正文与辅助文字达到 WCAG AA 对比度。
- 所有可点击文字具有不依赖颜色的可识别方式，例如下划线、箭头或明确动词。
- 视觉上克制的控件仍需提供至少 44×44px 的实际触控区域。
- 流式输出使用 `aria-live="polite"`，按字段或 Agent 完成播报，避免逐 token 朗读。
- 尊重 `prefers-reduced-motion`；本设计没有必要的持续动画。

## 13. 成功指标

- 在 390×844 视口中，除顶栏外至少 85% 的可见区域用于问题或回答正文。
- 正文在所有验收视口中不低于 16px，无横向滚动、裁切或文字重叠。
- 1、4、10 个 Agent 均能按配置顺序稳定渲染，返回顺序不导致章节重排。
- 用户无需展开操作即可阅读每个 Agent 的全部结构化回答。
- 用户可以在任一 Agent 章节结束后发起定向追问。
- 阅读状态下没有常驻输入框遮挡正文。
- 流式、完成、单 Agent 失败、全局错误和重试状态均可通过纯文字理解。

## 14. 验收标准

1. 现有头像、卡片背景、身份色、状态 pill、进度条和骨架动画从正文主流程移除。
2. 用户问题与 Agent 回答以单栏文档流呈现。
3. Agent 按设置中的顺序固定排列并原位流式输出。
4. 所有结构化字段默认展开；空字段不显示标题。
5. Agent 数量相关逻辑和文案完全动态化。
6. 追问与继续讨论按需打开编辑器；阅读时编辑器不常驻。
7. iOS safe-area、软键盘、自然滚动和文字选择均正常工作。
8. `npm run test`、`npm run build` 通过；可用的 lint 检查通过。
9. 使用移动端浏览器验证核心流程：提问 → 多 Agent 流式回答 → 自然阅读 → 定向追问 → 下一轮 → 线程切换。

## 15. 风险

- 完整展开多个长回答会形成很长的页面，需要严谨处理自动滚动与恢复阅读位置。
- 按需编辑器比常驻输入框少一个显性入口，空状态和章节末尾的操作文案必须清楚。
- 当前结构化字段可能随模型输出不稳定，缺失字段时排版必须自然收缩。
- 将 `AdvisorCard` 的视觉职责移除后，旧数据兼容渲染需要单独回归。

## 16. 假设

- 用户更重视完整信息和连续阅读，而不是快速并排比较观点。
- 当前结构化回答字段继续保留，UI 只改变展示方式。
- 线程管理、Provider 设置和模型选择功能保持不变。
- 本轮不重新设计深色模式；如现有深色模式不存在，则不新增。

## 17. 开放问题

没有阻塞实现的开放问题。具体文案可以在实现和移动端 QA 中微调，但不得改变本文已确认的单栏、完整展开、自然滚动、固定顺序和动态 Agent 原则。
